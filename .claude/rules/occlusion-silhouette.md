### Occlusion silhouette — the body shows through whatever covers it

**`shaders/occlusion_silhouette.gdshader` + `shaders/occlusion_silhouette_player_material.tres` + `scripts/occlusion_silhouette.gd` (`class_name OcclusionSilhouette`).** When something opaque covers part of a character, that part is drawn as a **1-px inner outline** (border pixels of the sprite) with a lightly filled interior — pixel-art clean, since 1 texel = 1 screen pixel. Front tiles (`*_alpha`) are now **opaque**: the old semi-transparency blended with whatever was behind each tile, so one building showed different greys depending on the background — unfixable by calibration.

- **How it detects cover — by colour, not by layers.** A copy of the character's sprite is drawn on top of the world (z 50 absolute) with a shader that, per body pixel, compares the colour the body **should** have there (`COLOR` = texel × modulate) with the colour **actually on screen** (`hint_screen_texture`). Equal → body visible → discard. Different → something is in front → silhouette. Chosen over a mask (a `SubViewport` seeing only "front" layers) because the mask needs per-**layer** visibility, so every building would have had to be split into two `TileMapLayer`s — multiplying level-design work. This needs nothing: any opaque thing in any layer works.
- **Consequences, by design:** anything drawn over the body triggers it, not only buildings — an enemy passing in front of the player shows the player's outline over it (**wanted**: the player never gets lost in the horde). Powers are excluded by draw order (z 60, see above). Visual effects are excluded the same way (z 51–59, e.g. `impact_01` at 53). A building pixel of exactly the body's colour hides one outline pixel — imperceptible.
- **The screen snapshot is taken once per frame**, when the first item using the screen texture draws; everything drawn later is not in it. That is the whole mechanism behind "powers at 60 don't trigger it".
- **The copy (`OcclusionSilhouette`, a `Sprite2D`) is created by code**, never placed by hand: `PlayerBase._attach_occlusion_silhouette()`, called by `player_character.gd` right after `sprite_node` is set — no player scene is edited, future characters get it free, and the chamber swap recreates it with the new player. Every frame it copies texture, flip, offset, region, frame, global transform **and `modulate`** (without the modulate, the red damage flash would light the outline over the whole body). **`process_priority = 100`** so it copies **after** the `AnimationPlayer` changes the frame — copying before would leave the copy one frame stale and flash the whole body on every frame change.
- **Calibration lives in the material**, one file for every player character (enemies have their own, see below): open `occlusion_silhouette_player_material.tres` → *Shader Parameters*: `outline_color` (white today), `fill_alpha` (interior opacity relative to the outline, 0.25), `tolerance` (colour distance treated as "the body itself" — raise it if false outlines appear in the open). The interior is the outline colour, not the character's own colours, by choice; showing the character dimmed instead is a small shader change if ever wanted.
- **Cost:** one screen copy per frame (trivial at 480×270); where nothing covers the body every fragment is discarded.
- **Enemies have it too, but ONLY over front tiles** — `scripts/occlusion_silhouette_animated.gd` (`class_name OcclusionSilhouetteAnimated`, an `AnimatedSprite2D` copying `sprite_frames`/`animation`/`frame`), created by `EnemyBase._attach_occlusion_silhouette()`, same shader but **their own material**, `shaders/occlusion_silhouette_enemy_material.tres` (red = danger, calibrated independently of the player's white). A per-enemy-type colour, if ever wanted, would be an Inspector field on each enemy scene choosing the material. Colour detection fires on *anything* in front, and in a horde enemies overlap constantly through Y-sort — the screen would fill with outlines. So the enemy copy stays **invisible** (shader not even run) unless its sprite rectangle touches a **front tile**, defined as a tile whose TileSet `z_index >= FrontTiles.MIN_Z` (4: the `*_alpha` tiles; back tiles are 0, Y-sorted decoration 2) — no extra marking in the TileSet. That rule lives in **`scripts/front_tiles.gd` (`class_name FrontTiles`, static `rect_touches(tree, global_rect)`)**, shared by every "only behind scenery" silhouette: front cells are indexed **once per scene** into a static `Dictionary` (rebuilt when `current_scene` changes; orphan cells skipped like in `SpawnManager`), so the per-frame check is a few hash lookups. Building the index happens on the first query of the scene — a one-off cost of reading every used cell.
- **Two precisions, and both are needed.** `rect_touches()` only switches the **whole** copy on or off. Inside, the shader's colour test cannot tell *what* covers a pixel — so an item half behind a building switched its copy on, and an enemy then walking over the item's **visible** half lit that half too (frequent in play). Fix: a **per-pixel cell map**. `FrontTiles` also builds, once per scene, an `ImageTexture` with **one pixel per world cell** (white = front tile, all layers merged in world coordinates), and `FrontTiles.bind_mask(tree, material)` hands it to the material (`front_mask`, `mask_origin`, `mask_cell_size`, `mask_size_cells`, `use_front_mask = true`) — called by every "only behind scenery" copy in `_ready()`. The shader's `vertex()` passes each pixel's **world position** (`MODEL_MATRIX * VERTEX`), and a pixel becomes silhouette only if its colour differs **and** its cell holds a front tile. These params are scene data written at runtime on the shared material (in memory only; the `.tres` keeps `use_front_mask = false`) — never calibrate them in the Inspector; the player never binds, so its outline still shows over enemies. **Precision is the 16-px cell, not the tile's art** (a transparent spot in a front tile's drawing still counts as front), and the map assumes **all tile layers share one grid** (same `tile_size`, no offset between layers — true today; a different `tile_size` warns).
- **XP items have it too, also only over front tiles**, in yellow (`shaders/occlusion_silhouette_item_material.tres`): `XPItem._attach_occlusion_silhouette()` creates an `OcclusionSilhouette` (the `Sprite2D` copy) on the item's `Sprite2D` with `only_over_front_tiles = true` — the same switch, off for the player. The `Shadow` sprite is not copied. A future collectible with its own script needs the same call (or a shared item base script).
- **Three materials, one shader:** `occlusion_silhouette_player_material.tres` (white), `occlusion_silhouette_enemy_material.tres` (red), `occlusion_silhouette_item_material.tres` (yellow), each referenced by `uid://` from its owner script — renaming a material in Godot's FileSystem keeps it working (the uid lives in the file). Known minor case: a ghosted enemy (Barrier phasing, low alpha) shows none, since the shader ignores near-transparent pixels.
