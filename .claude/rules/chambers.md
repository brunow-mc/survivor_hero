**Chambers — character swap in the safe house: `entities/stage_parts/chamber.tscn` + `scripts/chamber.gd` (`class_name Chamber`).** A glass sci-fi chamber with a character inside (art in `sprites/chambers/`, 64×64). Touching an **active** chamber swaps the character: hold → fade out → swap in the dark → fade in → release. Verified in play, including the chosen character carrying into stage01.
- **ONE scene for every character** — chambers differ only in data, set per instance in the Inspector (groups *Player*: `player_scene`; *Lock*: `locked`; *Visual*: `texture_unlocked`, `texture_locked`, `texture_empty`). A value set on an instance stays on it; nothing is shared because the script never mutates a resource, only which texture its own `Sprite2D` shows. **Never fill these on the base scene** (it would leak into every instance). `player_scene` is a `PackedScene` on purpose, unlike `stage_door`'s string: no cycle (a character never points back at the safe house) and loading small player scenes is cheap. A `PlayerData` resource per character would later replace these fields — only once a second consumer of that data exists.
- **Tree:** `Chamber` (Node2D, `z_index` 2, `y_sort_enabled`, origin = the **base** of the glass, same feet convention as entities) → `Sprite2D` (`centered` off, `offset` (−32, −60), base on the origin) · `Body` (StaticBody2D, layer 1, mask none; rotated capsule — the glass is solid) · `TouchArea` (Area2D, layer none, mask 2, `monitorable` off; rectangle **in front** of the base, `resource_local_to_scene`) · `ExitPoint` (Marker2D). Instances live **inside the `YSortContainer`**, named `ChamberNNXX` (`Chamber01MH`…).
- **Three states, in priority order:** **SELECTED** (it is `PlayerRosterGlobal`'s choice → `texture_empty`, touch ignored) → **LOCKED** (`texture_locked`, touch ignored) → **ACTIVE** (`texture_unlocked`, touch swaps). Every chamber listens to `PlayerRosterGlobal.selected_player_changed` and refreshes — so after a swap, in the dark, the used chamber goes empty and the previous character's chamber is "full" again: the swap tells itself through the images, with no extra code. Also applied in `_ready()` (a signal only reports transitions).
- **`_is_locked()` is the ONLY place that answers "locked?"** — today it returns the Inspector's `locked`; when a save system exists it will ask `PlayerRosterGlobal` (unlocks happen far from the chamber, e.g. beating a stage, so the truth belongs in the roster, already documented as the home of unlocks). Then `locked` becomes the pre-save default, or goes.
- **Minimal `@tool`:** in the editor each chamber draws its own image (`texture_locked` if `locked`, else `texture_unlocked`) and updates live as fields change — the empty image never shows in the editor, since "who is selected" is a match question. Barrier lessons applied: the `Sprite2D` is looked up inside `_refresh_visual()` (never `@onready`), and every game-logic path sits behind `Engine.is_editor_hint()` because autoloads do not exist in the editor.
- **The new character appears at that chamber's own `ExitPoint`** (like the room door's `ArrivalPoint`; move it per instance via Editable Children), never at the stage's `PlayerSpawner`, which stays for game start and the return from a stage. Diegetic (the character steps out of the chamber you chose) and scales to chambers in different rooms. No bounce: the used chamber is now SELECTED, and neighbours ignore touches during the hold. Init warning if the `ExitPoint` sits inside or within `EXIT_CLEARANCE` of its own `TouchArea`.
- **The swap, in order:** ignore if the player's input is held or the chamber is not ACTIVE → `HoldGlobal.hold(SCENE_ARRIVAL)` (the new character also hesitates: its attacks start only when the screen clears) → `fade_out(FADE_OUT_TIME)` → `PlayerRosterGlobal.select_player()` → old player **`remove_from_group("Player")` before `queue_free()`** (freeing only happens at the end of the frame, so the camera and the new player's test tools would otherwise find the old one) → `PlayerSpawner.spawn()` at the `ExitPoint` → `fade_in(FADE_IN_TIME)` → release. Durations are `chamber.gd` constants. The chamber asks for the hold, and it lives in `HoldGlobal` precisely because the player is destroyed mid-hold. The camera re-acquires the new player by itself; health is re-registered by the new player.
- **Swap sound** (group *Audio*: `swap_sound`, `swap_sound_volume_db`, `swap_sound_pitch_scale`, the project naming) plays at the touch, with the fade-out, via `AudioManagerGlobal.play_sound_2d()` at the chamber. **The pool is required here, not just convention:** the old player is freed mid-swap, so a player-owned `AudioStreamPlayer` would cut the sound; the pool's players belong to the autoload. Not stopped by any cleanup (`_end_current_scene()` runs only on scene changes; a restart mid-swap correctly silences it); the pool's players are pausable, so it pauses with the fade. **This value lives on the BASE scene** — the opposite of `player_scene` and the textures: it is the same for every chamber, so the base is its natural default, and a future chamber with another sound overrides only its own instance. Empty = legitimate silence (guarded, no warning).
- **Rules:** the safe house must **never** use `forced_player` (the empty image shows the roster's choice; a stage-imposed character would make the chambers lie). A swap is only legal in a scene **without enemies** — the chamber warns at init if the scene is in COMBAT. **Known gap, unreachable while no scene has both chambers and a `LoadoutBar`:** the bar connects to the player's controllers once, so after a swap it would keep the old character's icons. Its re-init enters when a scene has both.
