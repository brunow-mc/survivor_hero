### Scene changes — details

- **Named `go_to_scene()`, not `change_stage()`** (its first name): it serves menus, title and credits too, not only stages. Not `change_scene()` either — that was `SceneTree`'s own call in Godot 3, removed in 4.x, and would mislead anyone coming from an old tutorial. (Godot's own autoload tutorial calls the same piece `goto_scene()`.)
- **Called from a paused tree, it fades over the frozen scene.** Restart and Main Menu are pressed with the tree paused (pause menu, game over). `_go()` reads `get_tree().paused` and passes `while_paused` to the fade — detected, not a parameter, so no new caller has to remember it. The scene stays frozen under the black (no enemy moves); the cleanup unpauses in the dark, in the right order.
- **It leaves a menu state before darkening.** If the state is `PAUSED` or `PLAYER_DEAD`, it is reset to `COMBAT` (directly, bypassing `set_state()`'s dead guard) and `state_changed` is emitted — which **hides the pause and game-over menus** (each hides on seeing a state that is not its own) and unblocks the next stage's `StageConfig`, which `set_state()` would refuse from `PLAYER_DEAD`. The destination's `StageConfig` then declares the real mode; a non-stage scene (the main menu) keeps the autoload's default `COMBAT`, the documented safety net. `restart_game()` therefore no longer resets state itself before reloading — `_go()` does.
- **The Main Menu button used to be a raw `change_scene_to_file()`** after unpausing by hand: no cleanup (spawn kept running with a freed player, pool sounds crossed over, state stayed `PLAYER_DEAD` — a stage started from the menu the same raw way would be born dead) and no pause block. The `PauseMenu`'s `Reload_Timer` before restart is kept on purpose (a beat before the fade).
- Durations live with the caller: `stage_door.gd` (`FADE_OUT_TIME`/`FADE_IN_TIME`), `game_state.gd` (`RESTART_FADE_OUT_TIME`/`RESTART_FADE_IN_TIME`), `game_over_menu.gd` (`MAIN_MENU_FADE_OUT_TIME`/`MAIN_MENU_FADE_IN_TIME`). **Out and in are independent** — out runs in the old scene, in in the new one. **The fade-in is also the attack hesitation** (see `SCENE_ARRIVAL`), so each entry path into a stage can have its own wait.
- **The arrival hold is `SCENE_ARRIVAL`, not `TRANSITION`** — it also holds the start of the attacks until the fade-in ends (see *Brief holds*).
- **Shared cleanup `_end_current_scene()`**, used by both `go_to_scene()` and `restart_game()` — fixed once, valid for both: **silence every `AudioStreamPlayer`/`AudioStreamPlayer2D` of the outgoing scene (`find_children(..., owned = false)`, so code-created ones like the player's `audio_hit`/`audio_death` and the stage music are included) and the `AudioManager` pool, and only THEN unpause**; then XP reset, `stop_spawning()`, `TargetTrackerGlobal.clear_recent_targets()` (it held node refs to the dead scene's enemies, and restart never cleared it), `HoldGlobal.clear()`. **The silence-before-unpause order fixed a real bug**: pausing mid "ouch" and restarting played a fragment of the paused hit sound, because `restart_game()` unpaused first and the old scene lives until the end of the frame. The hit sound's own cycle (`can_play_hit_sound`, `finished`, `hit_post_delay`) was not touched.
- **`FadeGlobal.clear()` is deliberately NOT in the shared cleanup** — the black must survive the swap. **The cleanup zeroes every hold, including the one taken for the fade-out**, which is why `_swap_scene_in_dark()` asks for a second hold right after it; without it the player would be free during the swap in the dark.
- **The swap is awaited by comparison, not by frame count**: loop until `current_scene` is non-null and differs from the old one — frame counts depend on engine version details.
- **Pause is blocked for the whole transition** (`_changing_scene`, checked inside `pause_game()`, so every pause path obeys it — not just ESC in `InputManager`). The reason is mechanical, not only taste: between the old scene leaving the tree and the new one entering, **no pause menu exists** — the old one is out of the tree (pausing there raised `grab_focus` `!is_inside_tree()`) and the new one is not born yet. Room doors stay pausable: no scene change, no gap. `_go()` also uses `_changing_scene` to refuse a second scene change while one is running.
- Only menu states are cleared (see above); the destination's mode is never forced. Health, attack levels and stats reset for free because the new stage's `PlayerSpawner` creates a new player. An invalid path `push_error`s and releases screen, player and pause.
- **`forced_player` does not leak across stages** (verified): a safe house forcing `bo_girl` hands `stage_01` the roster's choice, not `bo_girl` — an override belongs to the stage that declares it. Testing that a **chosen** character survives a stage change needs something that writes `PlayerRosterGlobal` at runtime — a chamber. **Verified with the chambers:** the chosen character enters stage_01, survives death and restart, and its chamber is still empty back in the safe house.
