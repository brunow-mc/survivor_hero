### Enemy system

- **`scripts/enemy_base.gd`** — `CharacterBody2D` base: FSM (IDLE/WALK/DEAD), NavigationAgent2D pathfinding + **context-steering** inter-enemy avoidance (see *Enemy inter-enemy avoidance*), knockback with chain-transfer to adjacent enemies, item drops, `receive_hit()` / `die()`.
- **`_guard_against_position_jump()`** in `enemy_base.gd` — called every physics frame after `move_and_slide()`. Compares actual displacement against `velocity × delta × 3.0` (floor: 2 px); if exceeded, clamps the position back. This suppresses anomalous pixel-jumps that `move_and_slide()` produces when resolving collisions near walls or corners. Symptom that motivated it: enemies spawned or teleported near walls would visibly snap a few pixels in a random direction when the player moved toward/away from walls.
- Concrete enemies live in `entities/enemies/`. Enemies of the same archetype **share one script** and differ only by Inspector calibration (stats, sprites, `steer_*`). Enemy logic lives in **three layers**: `EnemyBase` (everything shared — FSM, movement, steering, knockback, drops, the `death_effect` scene, leaving the scene on death, contact damage) → **`enemy_chaser.gd`** (the "only chases the player" archetype: wires the concrete nodes to the base's generic vars) → a **per-enemy script only when the *logic* diverges** (a shooter, a flyer…), which extends `EnemyBase` directly and skips `enemy_chaser`. **`EnemyBase` finds the `Hitbox` node and connects its signals by code**, so a scene wires nothing and a new enemy deals contact damage from birth; a missing `Hitbox` warns once per scene. These are defaults: a script with another death or damage system overrides `dead_state()`, `die()`, `receive_hit()` or `_on_hitbox_area_entered/exited`. Animation is **scene data** (`SpriteFrames`), never in the script, so chasers with different sprites/frame-counts still share `enemy_chaser`. Named by archetype (`enemy_chaser`), not by instance (`enemy01`); no `class_name` for now (deliberate, revisit when a second archetype appears).
- Enemies belong to group `"Enemy"` (added by `enemy_base.gd`, not by the scene) and their `Hurtbox` to `"EnemyHurtbox"` (marked per scene) — see *Node groups*.
- After spawning or teleporting, always call `enemy.makepath()` to recalculate navigation from the new position.
- **Item drop system**: on `die()`, `EnemyBase` rolls `drop_chance` once, then drops `min/max_drop_amount` items around the body: several form a ring of exactly `drop_spread_radius`, and a single item stays at the centre. Each dropped unit is picked independently from `drop_table` (`Array[ItemDropData]`) via weighted random in `_choose_drop_item()` — same weight logic as `choose_enemy()`, null-safe. `ItemDropData` (`data/item_drop/item_drop_data.gd`) holds just `item_scene` + `spawn_weight`. Drop tables are configured as **embedded resources** in each enemy scene's Inspector (not `.tres` files), so different enemies can drop the same item with independent weights. New enemies need zero drop code — Inspector only.
- **`modulate` is split by channel between two visual effects — RGB vs alpha, each with a single owner.** Damage flash (`flash_red()`, export `flash_color`) writes only RGB via `_set_tint()`, which rebuilds the color keeping `anim.modulate.a` untouched. The Barrier ghost effect (`set_phasing()`, export `phase_alpha`) writes only `.a`. This is why `flash_color`'s own alpha is **ignored** — `_set_tint()` never reads `tint.a` — so the two effects don't stomp each other and can render simultaneously (an enemy can flash red while ghosted). This channel split is a **stopgap, not an architecture**: it only works because exactly two effects exist and each claimed a different channel by chance. A third effect wanting either channel (or changing damage flash to blink alpha) would conflict again — the real fix is a single "modulate arbitrator" that all effects report state to instead of writing `modulate` directly.
- **New enemy checklist**: origin at feet · `BodyCenter` node above it, normally at the collider centre · `NavigationAgent2D` as child of `BodyCenter` · `Hurtbox` in the `EnemyHurtbox` group (or the enemy is invulnerable) · a `Hitbox` node (or the enemy deals no contact damage) · fill the `Spawn Fit` group in its `EnemySpawnData` (see Spawn system) · root configured for Y-sort (`z_index = 2`, `y_sort_enabled = true` — see Y-sort). **A new "only chases" enemy needs no new script** — point its scene's root at `enemy_chaser.gd` and calibrate in the Inspector; write a script only when the *logic* differs (then extend `EnemyBase` directly, using `@onready` path `$BodyCenter/NavigationAgent2D`).
