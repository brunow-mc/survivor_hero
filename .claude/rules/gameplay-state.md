### GameplayState — details

The rules that apply to every system (state vs progression, the combat gate, returning to the previous state, each stage declaring its mode) live in `CLAUDE.md`.

**Why a blocklist, and the risk it carries.** `EXPLORATION` sat in the enum for a long time without being in `is_combat_allowed()`'s list — entering it would have blocked nothing, and the safe house would have had the player attacking. An allowlist (`current_state in [COMBAT]`) would fail safe instead, since forgetting would read as "the player can't attack", visible in seconds, rather than "the player attacked during the cutscene", which hides. Deliberately unchanged for now: most of the game is combat. Revisit before `DIALOGUE` and `CUTSCENE` are actually entered.

**EXPLORATION with a spawner is a "ghost mode".** Spawning, enemy movement and XP-item magnet movement stop only when the whole tree is paused (`get_tree().paused`), which PAUSED and UPGRADE do and EXPLORATION does not. So a stage in EXPLORATION that still has a `SpawnManagerConfig` makes the horde spawn and chase, XP items follow the player forever without ever being collected (the gate covers the *pickup*, not the approach), and nobody can hurt anybody. Verified in play, and **correct for what exists** — a real safe house has no spawner and no enemies dropping items, so none of it is reachable there. It becomes a real decision only for a future **mixed** stage (a safe zone inside a combat map), where items already on the ground would hover and then all be collected at once when combat resumes. Treat "which systems should EXPLORATION freeze?" as an open design question, not as three separate bugs.

**"Freeze" is actually THREE things, with different mechanisms — do not bundle them.** **Tap** = stop *creating* (spawn); **brake** = stop what already exists from acting (enemy movement, XP-item approach); **purge** = *remove* what already exists (enemies, items on the ground). Tap and brake are states and fit `is_combat_allowed()` — a consumer asks a question. **Purge cannot be a boolean at all:** a state says "what may happen now", never "what should happen at the moment of the switch", so it belongs to the `state_changed` signal, i.e. to the trigger that caused the transition. And the modes disagree about it — `CUTSCENE` and `DIALOGUE` want the brake and must **refuse** the purge (the horde has to still be there afterwards), while a between-waves breather wants the purge as the *point* of the mechanic. Two consequences to expect: `state_changed(new_state)` carries only the destination, so a purge handler needs the **previous** state added to it (a signature change touching every listener); and purging via `EnemyBase.die()` would **drop items** exactly while pickup is blocked, so it needs a death without drops. Note the first mixed stage probably needs **only the tap**: a safe room closed off by a `Barrier` separates the horde physically, so brake and purge never become reachable.

**The level-up menu keeps its own memory of the previous state.** It restores `LevelUpManager._state_before_upgrade`, captured at the moment it opens, instead of reading `previous_state`, because that is a single slot any transition overwrites. Two details make it hold: the capture is skipped when already in UPGRADE (chained menus re-enter the opening function, and would otherwise record UPGRADE as the origin), and **pause cannot nest inside this menu at all** — `level_up_ui.gd` swallows the `pause` action in `_input()` while visible, before `InputManager` ever sees it in `_unhandled_input()`. That block has existed since the first commit; reading `InputManager`'s `match` alone suggests pause works everywhere, which is wrong. **The one deliberate COMBAT write is in `GameStateGlobal._go()`**, shared by `restart_game()` and `go_to_scene()`: leaving PAUSED or PLAYER_DEAD for a scene change resets the state to COMBAT, and the new stage then declares its own mode.

**`StageConfig` details** (`entities/stage_parts/stage_config.tscn`, `scripts/stage_config.gd`). The autoload's initial value (COMBAT) is deliberately kept as the safety net for scenes that are **not** stages (title screen, game over) — those must not warn for lacking the node.

- **Why it is required, not cosmetic:** `GameStateGlobal` is an autoload, so the state **survives a scene change**. Without a per-stage declaration a stage inherits the previous one's mode — leaving a safe house in EXPLORATION would hand the next combat stage a run with attacks, damage and XP all blocked, silently. That is why combat stages declare COMBAT too.
- **It declares in `_enter_tree()`**, same reasoning as *NavmeshMerger*: every `_enter_tree()` runs before any `_ready()`, so the mode is set before the player, `AttackController` and `SpawnManager` start — **regardless of where the node sits in the stage tree**. Verified in the console: its line prints before every other init line.
- **The `@export` exposes the WHOLE `GameplayState` enum on purpose.** Restricting it to COMBAT + EXPLORATION was proposed and rejected as an artificial limit: a title/intro stage can legitimately open in CUTSCENE, a purely narrative scene in DIALOGUE, and future states (SHOP, BOSS_INTRO…) appear in the list without touching the script. Typing the export as `GameState.GameplayState` (the `class_name` on `game_state.gd`) is what gives a real Inspector dropdown **without duplicating the state names** — never re-list them in an `@export_enum`.
- **Only three values are refused, for mechanical reasons, in `FORBIDDEN_STATES`:** `UPGRADE` (owned by `LevelUpManager`, which pauses the tree expecting to close a menu later — a stage born there has no menu to close), `PAUSED` (`pause_game()` changes the enum **and** pauses the tree; declaring it via `set_state()` would do only the first, and `resume_game()` only exits from it) and `PLAYER_DEAD` (terminal — `set_state()` itself refuses to leave it). The node `push_warning`s and **does not apply** the mode, leaving the game running.
- `restart_game()` (through `_go()`) leaves the menu state for COMBAT *before* `reload_current_scene()`, and the reloaded stage then re-declares its own mode — verified in play, so a safe house survives a restart correctly.
- **`start_hold_seconds`** (group *Start*, default `0` = off): the stage-start hold — seconds of frozen hesitation (player, attack start, enemies, spawn clock) **after** the screen clears. Calibrated per stage on the instance; the safe house leaves it at 0. See *Brief holds*.
