MUDANÇA FUNDAMENTAL NESTA VERSÃO:
----------------------------------

PowerUpData agora usa MÉTODO ACUMULATIVO (igual ao AttackController).
Valores em arrays são SOMADOS ao longo dos levels, não SUBSTITUÍDOS.

ANTES (v1.3.5 - MÉTODO DE SUBSTITUIÇÃO):
  max_health_flat_per_level = [20, 40, 60, 80, 100]
  Level 1: HP = 20
  Level 2: HP = 40
  Level 3: HP = 60
  Level 4: HP = 80
  Level 5: HP = 100

DEPOIS (v1.3.6 - MÉTODO ACUMULATIVO):
  max_health_flat_per_level = [20, 20, 20, 20, 20]
  Level 1: HP = 20
  Level 2: HP = 20+20 = 40
  Level 3: HP = 20+20+20 = 60
  Level 4: HP = 20+20+20+20 = 80
  Level 5: HP = 20+20+20+20+20 = 100


ARQUIVO MODIFICADO:
-------------------

1. data/power_up_data/power_up_data.gd
   
   Função _get_value() agora SOMA valores:
   
   ANTES:
     func _get_value(arr: Array[float]) -> float:
         if current_level <= 0:
             return 0.0
         var index = current_level - 1
         if index < arr.size():
             return arr[index]  # ← SUBSTITUIÇÃO
         return 0.0
   
   DEPOIS:
     func _get_value(arr: Array[float]) -> float:
         if current_level <= 0:
             return 0.0
         var total = 0.0
         var max_index = min(current_level, arr.size())
         for i in range(max_index):
             total += arr[i]  # ← ACUMULATIVO (SOMA)
         return total

BENEFÍCIOS DO MÉTODO ACUMULATIVO:
----------------------------------

1. CONSISTÊNCIA COM ATTACKCONTROLLER:
   • Ambos sistemas usam o mesmo padrão
   • Fácil entender e manter código

2. CONFIGURAÇÃO INTUITIVA:
   • Arrays representam INCREMENTOS, não valores finais
   • "Quanto adiciono em cada level?" ao invés de "Qual o valor total?"
   
3. FLEXIBILIDADE:
   • Fácil criar progressões variadas
   • Exemplo: [20, 20, 20, 50, 100] = começa linear, depois escala
   
4. BALANCEAMENTO:
   • Mais fácil balancear early vs late game
   • Incrementos visíveis por level

Os valores finais de cada powerup em cada level são IDÊNTICOS à v1.3.5.
